# Changelog

## [Unreleased]

### Added

- **Tool-enabled streaming requests are now cacheable** (`cache.cache_tool_streams`, default on) (#43). Measurement showed Cradle's dominant real traffic — Open-WebUI chat turns, which carry `tools` and `stream:true` — was **100% BYPASS**: not cached, full upstream cost every time, because the streaming wrap path can't carry a tool-call response so all tool-streams were refused up front. Only Open-WebUI's internal task calls (title/tags/follow-ups, no tools) ever hit the cache. Cradle now routes a `stream+tools` request through a new path that tees the response to the client **verbatim** (so a tool call relays intact) while accumulating a copy, and caches it **only** when it contains no tool call — in the same reconstructed representation the non-streaming path uses (JSON and streaming share a cache key). The gate is fail-closed: a response is cached only on a parsed terminal `finish_reason` of `stop`/`eos`, with no upstream error, no tool call, no streaming-delta field outside `{role, content}` (so legacy `function_call`, reasoning, refusal, etc. disable caching rather than being dropped on replay), no unparseable framing, and the client still connected. A tool-call response reaches the client untouched and is never cached; the client stream is never derived from Cradle's parsing, so a parse failure only forgoes a cache write. This brings the chat path from 0% cacheable to the L1 tier of non-streaming tool requests (which were already cached). Set `cache.cache_tool_streams: false` to restore the previous always-bypass behavior; `stream+logprobs` still bypasses. **Accepted risk:** the volatility guard is a regex over user text and does not inspect tool semantics, so a stateful tool with no time-word (e.g. "what's my balance") can serve a stale cached text answer under this flag. Verified end-to-end on a running instance: a tool-enabled streaming request answered in text caches and replays (MISS→HIT-L1), while one that emits a tool call relays the tool call and stays MISS. Design reviewed by a second model (codex) + advisor. See `DECISIONS.md` ADR-0006. (Closes #43)
- **Structured, configurable request logging.** Watching Cradle's logs previously showed only uvicorn's access lines — nothing about what Cradle *decided* per request. Two causes, both fixed: `python -m cradle` started uvicorn with no logging configuration, so the `cradle` loggers sat at WARNING and every request-path line was dropped before it left the process; and the request path emitted no lines at all (all per-request facts went only to response headers and Prometheus). Cradle now installs its own handler at startup and emits **one structured line per request** on the `cradle.request` logger, carrying the cache decision (`l1`/`l2`/`miss`/`bypass`), model, hashed tenant + cache key, L2 similarity, guard/rerank/volatile/audit annotations, per-stage timings, and token counts. Verbosity is configurable on **two independent axes** (new `logging:` config section / `CRADLE_LOGGING__*` env vars): `logging.level` (`INFO` = one line per request; `DEBUG` = also a line per rejected L2 candidate with its key + score) and `logging.content` (`none` default = keys/hashes/scores/timings only; `prompts` adds the request text; `prompts_and_completions` adds the response text — logged text truncated to `logging.max_text_chars`). The axes are deliberately separate so a production tenant can be debugged at `DEBUG` without dumping its prompts. All sensitive fields pass through one redaction chokepoint, and a `content: none` test asserts no prompt/response text appears on any terminal path — the enforceable form of the "no prompt text in logs by default" rule (`logging.content` is the request-path analogue of `l2.audit_log_text`; DESIGN.md's flat rule is relaxed to "by default" in ADR-0004). `logging.format` defaults to human-readable `key=value` with `json` as the aggregator opt-in; only the `cradle` logger tree is configured, so uvicorn's access log is untouched. A client that disconnects mid-stream now still logs a line (`disconnected=true`), and two previously-silent failures (embed error, rerank fail-open) now log their traceback. See `RUNBOOK.md` §4.4 and `DECISIONS.md` ADR-0004.
- **GPU rerank deploy path** (`l2.rerank_device: cuda`), #31. The config option and the `rerank-gpu` extra existed, but there was no runnable way to deploy them: the image ran a plain `uv sync` (CPU `onnxruntime`), compose granted no GPU, and `python:3.12-slim` has none of the CUDA 12 / cuDNN 9 libraries `onnxruntime-gpu` needs — so `rerank_device: cuda` crash-looped at startup (`Provider CUDAExecutionProvider is not available`). Now there's a real path: `docker/Dockerfile.gpu` (a `nvidia/cuda:13.0.1-cudnn-runtime` base that swaps in `onnxruntime-gpu` for the CPU build — they can't coexist — and bakes the same models) and `docker-compose-gpu.yml` (grants the GPU via `gpus: all` + sets `CRADLE_L2__RERANK_DEVICE=cuda`), run with `cp docker-compose-gpu.yml docker-compose.yml && docker compose up --build` on a host with an NVIDIA GPU + Container Toolkit. GPU rerank is ~2–5 ms/hit vs ~15–40 ms on CPU. The **default image is unchanged** (CPU, `python:3.12-slim`). And `rerank_device: cuda` on the CPU image now fails fast with an **actionable** error (naming the GPU image and the `cpu` fallback, and noting that the `AzureExecutionProvider` in the provider list is inert CPU-wheel baggage, not the missing one) instead of the raw fastembed `ValueError`. See `RUNBOOK.md` §1.4.
- **Production runbook (`RUNBOOK.md`).** A single operations home: deploy (compose + first-deploy traps like the gitignored `config/cradle.yaml`), verify-it's-up-and-it's-Cradle (health/readiness semantics, and the `/v1/models` single-backend passthrough gotcha — no `x-cradle-*` headers, so confirm via `POST`), capacity/hard limits (single uvicorn worker while L2 is on; the ~20k Qdrant-local point ceiling with `l2.mode=server` unimplemented in v1), monitoring (which of the ~19 `cradle_*` metrics matter and what to alert on), a symptom→cause→action troubleshooting table built from real incidents (#24 empty self-heal, #18 refresh L2 staleness, wrap-stream usage loss, reranker-load 503), probe-driven tuning, and recovery/rollback (the `pipeline_version` bump as the safe whole-cache invalidation lever; destructive wipes marked as operator-run). Scoped to operations only and cross-linking DESIGN/README rather than restating them (`DECISIONS.md` ADR-0002); kept in lock-step with config/metric/health/limit/header changes and carrying a dated "verified against the live system" header.
- **Cache probe mode.** `X-Cradle-Cache-Control: probe` runs the whole read-side decision — L1 lookup, embed, L2 top-K, guard, rerank — and returns a JSON explanation (`cache`, `would_call_upstream`, the L1 key, and every examined L2 candidate with its cosine, guard and rerank outcome) instead of a completion. It never writes to either cache and never calls upstream, so tuning `cosine_threshold` / `rerank_threshold` or answering "why did this hit?" is a `curl` rather than a paid round-trip. Marked by `X-Cradle-Probe: 1` and counted in `cradle_cache_probes_total{cache}`.
- **Volatility guard: time-sensitive prompts get a short TTL automatically.** A correct semantic match replayed after the answer changed ("latest version of X", "current price", "today's date", weather, news) was the one stale-answer failure the cosine gate, guard and reranker all agree on. Cradle now classifies each cacheable prompt's user text against a conservative pattern table and stores volatile prompts with `cache.volatile_ttl_s` (default 300 s; `0` = never store) instead of the 24 h default. A client's explicit `X-Cradle-Cache-TTL` always wins; system-prompt dates do not count. Observable via `X-Cradle-Volatile: <reason>` and `cradle_volatile_prompts_total{reason}`; `cache.volatility_guard: false` disables it. L2 → L1 promotion now honors the per-request TTL too (previously it always used the default).
- **Property-based tests** (`tests/test_properties.py`, Hypothesis) for the invariant-heavy core: the protected-span extractor round-trips any text and its spans survive fluff stripping; fluff stripping is idempotent and never grows text; canonical text ignores whitespace outside protected spans; the L1 key ignores field order and `tools: []` vs `null` but changes on any extra; the sampling fingerprint ignores messages but not sampling; a synthesized cache-hit SSE stream parses back to the stored body. One known non-fixed-point of text canonicalization is pinned as a strict xfail with its counterexample. `CRADLE_HYPOTHESIS_MAX` raises the example count locally.
- **Verified L2: audit-sampled semantic hits, a measured false-hit rate, per-entry learned floors, and self-heal** (`l2.audit_rate`, default `0` = off). Cradle's promise is "a miss beats a wrong hit", but nothing ever measured how often an L2 hit was wrong in production. Now, with probability `audit_rate`, a served L2 hit is re-asked upstream *in the background* (the response is never delayed) and a judge decides whether the fresh answer agrees with the served one. The default judge is the cross-encoder reranker Cradle already loads (`l2.audit_judge: auto`): measured on `bge-reranker-base`, same-meaning answers score ≥ 7.2 and contradictory ones ≤ 2.1 (Mercury-closest vs Neptune-farthest: −0.46), so the existing 4.0 threshold separates them; answer-embedding cosine is only a fallback because it cannot (same 0.83–0.98 overlaps wrong 0.73–0.92). Each audit is a labeled observation: it is counted in `cradle_l2_audit_total{verdict="agree|disagree|error"}` (a real false-hit rate on real traffic), its raw judge score lands in `cradle_l2_audit_answer_score{judge}`, and it is appended to `{data_dir}/audits.jsonl` (keys and scores only unless `l2.audit_log_text: true`) for offline threshold calibration. A **disagree** does two things: the served entry learns an `audit_floor` (the highest similarity at which it was judged wrong) and refuses future matches at or below it (`X-Cradle-Guard: reject:audit-floor`); and the fresh answer is written back under the querying prompt's own key, so the next paraphrase hits the right entry. Sampled hits carry `X-Cradle-Audit: scheduled`. Inspired by vCache's per-entry thresholds and Krites' off-critical-path verification, reduced to a monotone rule with no cold start. Audits spend real upstream calls with the client's forwarded credentials after its response completes; 1–5 % is the sensible range.
- **Per-request cache controls.** Clients can now steer caching per request: `X-Cradle-Cache-Control: no-store` (don't store this response), `no-cache` / `refresh` (skip the cache read, force a fresh upstream call), and `X-Cradle-Cache-TTL: <seconds>` (override the default TTL, clamped to the configured max; `0` = don't store). Lets a client mix stable prompts with sensitive or time-sensitive ones without a global config change.
- **L2 top-K candidate selection** (`l2.query_top_k`, default 5). The semantic cache now retrieves the top-K nearest candidates above the cosine floor and serves the first that survives the guard + rerank, instead of only the single nearest neighbor. When the nearest match is a near-miss the guard/rerank rejects, a genuine paraphrase at rank 2..K still serves — raising hit rate without lowering the cosine floor.
- **Write-quality gate.** Cradle no longer caches low-quality responses: only `finish_reason: stop`/`eos` with non-empty content is stored. Truncated (`length`), refused (`content_filter`), tool-call, and empty responses are no longer written back (and thus never replayed to a prompt or its paraphrases). Skips are counted in `cradle_cache_write_skips_total{reason}`.
- L2 semantic-cache **cross-encoder rerank** (default on, `features.l2_rerank`): after the cheap numbers/negation guard, a `BAAI/bge-reranker-base` cross-encoder re-scores the surviving candidate and rejects it below a threshold. This closes the **named-entity-swap** gap the guard cannot see — verified live, "capital of Germany" now returns Berlin instead of the cached "Paris" (reject score −3.5). Runs only on candidates that already passed the cosine gate and guard; **fails open** (an unavailable or erroring reranker serves the already-twice-gated hit rather than forcing a miss). Observable via `X-Cradle-Rerank` (`pass:<score>` / `reject:<score>` / `fail-open`) and `cradle_l2_rerank_rejects_total` / `cradle_l2_rerank_fail_open_total`. **Residual gap:** antonym swaps (closest/farthest, largest/smallest-direction) score in the paraphrase range and are not reliably caught — same fundamental limitation as negation. Cost: the reranker adds ~15–40ms per L2 hit and ~1.1GB to the image — see the DESIGN decision on the L2 latency budget. (#5)
- L2 semantic-cache **precision guard**: before serving a semantic hit, Cradle now compares the query against the stored candidate and rejects the hit when their numbers or negation differ, then falls through to a real upstream call. This stops the cache from returning a stale wrong answer to a near-miss prompt — e.g. a "convert 200 USD" request no longer replays the "100 USD" answer, and "is X true?" no longer replays the answer to "is X NOT true?". A rejection is observable via the new `X-Cradle-Guard: reject:<reason>` response header and the `cradle_l2_guard_rejects_total{reason}` metric. Known gap: single-entity swaps (capital of France vs Germany) are not caught by this guard and need a cross-encoder (tracked in #5). (#5)
- v1 Cradle pass-through API gateway: OpenAI-compatible `/v1/chat/completions` with L1 diskcache, L2 Qdrant local + FastEmbed, rule-based compression, prefix/suffix reconstruction, Prometheus metrics, and a fixture eval harness. No live LLM required for tests.
- Runnable multi-stage Docker image (`uv sync --frozen`) and Compose stack. FastEmbed weights bake into `/opt/cradle/models/fastembed` so the `/data` volume does not hide them. Compose reaches a host-side upstream via `host.docker.internal`. CI builds `docker-compose-ci.yml` and smokes `/healthz` + `/readyz`.
- Docker image now also bakes the `bge-reranker-base` cross-encoder (`BAKE_RERANK=1`, default) into `/opt/cradle/models/fastembed`, so a fresh container is self-contained and does not download the ~1.1GB reranker at startup warm-up (needing HF network access). Set `BAKE_RERANK=0` to skip when rerank is disabled.
- `HF_TOKEN` build arg (Dockerfile) + Compose passthrough, so the image bake steps can authenticate Hugging Face model downloads (gated or rate-limited pulls). Documented in `.env.example`; optional, empty = anonymous.

### Changed

- **Runtime config is now bind-mounted, not baked into the image, so a config edit is a restart — not a rebuild** (#36). `config/cradle.yaml` was `COPY`-ed into the image at build time and `CRADLE_CONFIG` pointed at the baked copy, while compose mounted only the `/data` volume. Two failures fell out of that: (1) editing the host `config/cradle.yaml` and restarting did nothing — the container kept reading the copy frozen at build time, so on the LAN GPU box `max_body_bytes: 1048576` pinned the request-body cap at 1 MiB **through two rebuilds** after the code default was raised to 128 MiB (#34); and (2) because the file is gitignored, `COPY config` captured whatever happened to be in the working tree — never reviewed, free to drift from `.example`, and able to crash-loop a box after an upgrade if it still listed a removed key (`extra="forbid"`, the #27 shape). The compose templates now bind-mount the config directory read-only (`./config:/app/config:ro`) and the image bakes only `cradle.yaml.example` — never a runtime `cradle.yaml`. A config change now takes effect on `docker compose restart cradle` with no rebuild; with no host `config/cradle.yaml` present, Cradle runs on the built-in pydantic defaults exactly as before. The whole `config/` dir (always present in a clone) is mounted rather than the file (absent in a fresh clone, which compose would otherwise auto-create as an empty directory). This does **not** un-gitignore the config — the deliberate "copy the example, edit locally" workflow is unchanged; it only decouples the config from the image build. Verified end-to-end on the CPU image (edit + restart round-trip, `#27`-shape crash-and-recover, fresh-clone-with-no-file up). A drift guard (`tests/test_config.py::test_example_config_validates`) now loads the tracked `cradle.yaml.example` through the real settings class in CI, so a key the code drops but the example keeps fails the suite instead of a box at boot. **Action required:** `docker-compose.yml` is the gitignored working copy, so re-copy your template (`cp docker-compose-cpu.yml docker-compose.yml`, or the GPU one) to pick up the new `volumes:` mount — otherwise the fix is in the repo but not on the box. Note this makes host config edits *take effect*, it does not *change* them: a box whose `config/cradle.yaml` still sets a stale value (e.g. `max_body_bytes: 1048576` on the LAN GPU box) keeps that value until you edit the line — audit each box's `config/cradle.yaml` against `.example` after re-copying the compose template. (#36)
- **Request body cap raised 1 MiB → 128 MiB, and enforced before buffering** (#34). The old 1 MiB `server.max_body_bytes` capped prompts at ~260K tokens and returned `413` for long-context (a 1M-token prompt is ~4–6 MB) and multimodal requests (inline base64 images are ~30–45 MB for a handful of photos) that the upstream model would happily accept — the wrong behavior for a pass-through gateway. The default is now 128 MiB, sized for those while still rejecting gigabyte-scale abuse; lower it for text-only deploys. Cradle also now rejects an oversized request on its declared `Content-Length` **before** reading the body into memory (the old check buffered the whole body first, so the "DoS guard" allocated it before the 413); a post-read backstop still catches a chunked or understated `Content-Length`. **No operator action required** — a higher cap only accepts more. (A chunked body with no `Content-Length` is still fully buffered before the backstop; bound it with a reverse proxy if needed.)
- **Compose files renamed to a consistent `docker-compose-*.yml` scheme, and the GPU one is now standalone.** `docker-compose.yml` → `docker-compose-cpu.yml` (default, CPU rerank), `compose.gpu.yml` → `docker-compose-gpu.yml` (now a **complete standalone** template, not an `-f` override), `compose.ci.yml` → `docker-compose-ci.yml` (CI workflow updated). Deploy is now "copy the template you want to `docker-compose.yml` (gitignored local working copy), then plain `docker compose up`" — no `-f` juggling. The GPU template grants the GPU via `gpus: all` (the form plain `docker compose up` honors); the previous override-only form used `deploy.resources.reservations.devices`, which `docker compose up` does not reliably apply — it could start the container **without** a GPU (rerank silently falling open to CPU, `libcuda.so.1: cannot open` in the logs). Verified working on an RTX 4080 host. **Action if you script against the old names:** update `compose.ci.yml`/`compose.gpu.yml`/`docker-compose.yml` references.
- **Removed the dead `cache.evict_old_pipeline` config key** (#27). It was declared, shipped in `config/cradle.yaml.example`, and defaulted `true`, but nothing in the code ever read it — it promised to evict old-`pipeline_version` cache entries on startup (DESIGN.md) and did not. Old-version entries were, and still are, filtered out of reads and aged out on TTL; there is no startup eviction. **Action required only if you set it:** `cache` uses `extra="forbid"`, so a `cradle.yaml` that still lists `evict_old_pipeline` now fails to load — remove the line. Behavior is unchanged, and a `pipeline_version` bump remains reversible within the entries' TTL (see `RUNBOOK.md` §7.2).
- **Upstream rate-limit / retry headers now reach the caller.** On upstream errors (e.g. 429/503) and on bypass passthrough streams, Cradle relays an allowlist of upstream response headers — `retry-after`, `x-ratelimit-*`, and the upstream request id (renamed to `x-cradle-upstream-request-id` so it never clobbers Cradle's own `X-Request-ID`). Previously `chat()`/`start_chat_stream()` returned only the JSON body, so a client's backoff on a 429 had no `retry-after` to honor. Body-framing and hop-by-hop headers (`content-length`, `content-encoding`, `transfer-encoding`) are deliberately never forwarded — they describe Cradle's re-framed body, not the upstream's, and forwarding them corrupts the response.
- **`/v1/models` reflects the real upstream model in single-backend deploys.** When no named `upstreams`/`routes` are configured (fallback-only, the default), Cradle now proxies `/v1/models` to the upstream and returns what it actually serves — instead of the static `upstream.models` placeholder. So a client (e.g. Open WebUI) shows the real model in its picker with no config. With named routes present, the static advertised list is kept (proxying one backend would be ambiguous). The explicit `upstream.models_passthrough` flag still forces passthrough. If the upstream is unreachable, `/v1/models` falls back to the static list rather than erroring (clients poll it on every connection check).
- Renamed `compose.yml` to `docker-compose.yml`.
- `config/cradle.yaml` is now gitignored with `config/cradle.yaml.example` as the tracked template — copy the example to the real filename before running, so local config edits no longer conflict on every `git pull`.
- Product copy: Cradle is a gateway clients point at, not a local companion app for a model runtime.
- Default auth is intercept mode: no Cradle API key. Client `Authorization` is forwarded upstream; cache isolation is SHA-256 of that token. Optional `auth.keys` remains an allowlist.
- Model glob `routes` send a request to a named OpenAI-compatible `upstreams` entry (OpenAI, xAI, llama.cpp, LiteLLM). Unmatched models use `upstream.base_url`.

### Fixed

- **Reasoning models no longer lose their `reasoning_content` through Cradle (live data loss + cache pollution)** (#49). On the wrap path (plain `stream:true`, no tools — the shape a reasoning model's chat turns take), Cradle rebuilt the client stream from parsing and forwarded only `content` deltas, so a reasoning model's thinking was **silently dropped from the live client stream** — a pass-through gateway altering the response, no cache involved. It then **cached the reasoning-stripped answer** and replayed it. Verified live on `meta/muse-glimmer-30B`: a plain stream showed only content frames and zero `reasoning_content`, and the repeat was a HIT of the stripped answer. Cradle now accumulates reasoning separately and emits it on its own SSE frame (before content, matching the upstream shape), on both the wrap and passthrough paths, and stores it in the cache record so a HIT replay carries the thinking too. Verified live against the real model built from this branch: a plain stream forwards `reasoning_content` (330 frames on a miss) and MISS→HIT-L1 both carry reasoning. `refusal`/legacy `function_call` deltas still disable caching. (Closes #49)
- **Reasoning-model tool-streams are now cacheable** (#46). #43's tool-stream caching refused any stream carrying a delta outside `{role,content,tool_calls}`, so a reasoning model (which emits `reasoning_content`) never cached — #44's benefit didn't reach reasoning models, even though the JSON path already cached them faithfully (`merge()` preserves the field). The delta classification is now 3-way: cache+replay `{role,content,tool_calls}`; **cache + accumulate + replay** `{reasoning_content,reasoning}`; never-cache everything else (`refusal`, legacy `function_call`, unknown). Tool-call detection is independent of reasoning deltas, so caching stays correct (a tool-call response is still never cached). Brings the streaming path to parity with the JSON path; no config flag (strictly better). (Closes #46)
- **Tool-stream cache-write skips now report the true reason, not a misleading `finish_None`.** On the #43 passthrough-cache path, a stream that Cradle refuses to cache because it carries a field the content-only representation can't replay (a `reasoning_content` delta, a legacy `function_call`, an unparseable frame — `cache_disabled`) or because upstream errored was still labelled `cradle_cache_write_skips_total{reason="finish_None"}`. Cause: the accumulator stops parsing once it aborts, so `finish_reason` is never captured and the reconstructed completion looks like it "ended with no finish_reason" — even when the wire clearly ended with `finish_reason:"stop"`. The gate read that shape artifact *before* the real abort cause. Observed live: a reasoning model (`meta/muse-glimmer-30B` on llama.cpp) emitting `reasoning_content` produced a steadily climbing `finish_None` count that pointed operators at the wrong thing (a supposed upstream framing bug) instead of the real one (the response is legitimately un-cacheable because it contains reasoning). The ordered gate now lives in a pure, unit-tested `passthrough_skip_reason()` that checks `upstream_error` and `unsupported_stream` (the aborting causes) before the completion-shape gates, so the recorded reason names the root cause. No change to *what* caches — only to the reported reason; a genuine no-finish-reason stream still reports `finish_None`. `unsupported_stream` now names its true cases (legacy `function_call`, `refusal`); reasoning is no longer one of them (see the reasoning-stream entry below). See `RUNBOOK.md` §5.
- **L2 semantic cache no longer serves wrong answers when a large shared system prompt dominates the embedding** (#40). On a live instance (open-webui traffic, one big fixed system prompt on every request), an L2 hit served an answer belonging to a *different* user task as a `200`: a "riff on these creative prompts" request was served a title-generation answer at `sim=0.987 rerank=pass:7.59`. Root cause: `embed_text` (what L2 matches on) was built from **all** messages, system prompt included. When the system prompt is a large block identical across requests, it dominates the embedding — the short discriminating user turn is a fraction of the vector — so two unrelated user questions land at very high cosine and both the cosine gate and the cross-encoder rerank are diluted the same way and pass. Measured on the real bge models (thresholds cosine 0.90 / rerank 4.0), two different user tasks under one shared system prompt scored 0.93 / 6.27 (both pass → false hit) with the system prompt embedded, and 0.61 / −4.61 (both reject → correct miss) without it. Cradle now builds `embed_text` from **user/assistant turns only**; the system prompt still gates correctness and saves tokens via `system_prompt_version` scoping and the L1 key — it just no longer pollutes response matching. A system-only request (empty `embed_text`) is now L2-ineligible. Verified end-to-end on a live instance: two different tasks under the same big system prompt now both MISS (correct answers), while a genuine paraphrase of one still HITs (`sim=0.953 rerank=pass:9.58`). **Operator-visible:** `pipeline_version` is bumped **v2→v3** so pre-fix L2/L1 entries (embedded from system+user) miss and age out on TTL — hit rate drops until the cache refills. `embed_text` now means "matchable content," not "the prompt," so the `logging.content` `prompt=` field and the `audits.jsonl` `query_text`/`candidate_text` rows carry user/assistant turns only. See `DECISIONS.md` ADR-0005, `DESIGN.md`, `RUNBOOK.md` §7.2. (Closes #40)
- **Upstream requests no longer carry sampling defaults the client never sent.** Cradle forwarded `model_dump(exclude_none=True)`, and `ChatRequest` declares OpenAI's defaults for `temperature` (1.0), `top_p` (1.0), `presence_penalty`/`frequency_penalty` (0.0), `n` (1) and `stream` (false) — so a client that sent only `model` + `messages` reached the backend with `temperature: 1.0, top_p: 1.0` injected. On backends with their own defaults (llama.cpp, vLLM, Ollama) this silently overrode server-side sampling (llama.cpp's own temperature 0.8 / top_p 0.95 / top_k / min_p were ignored), so a "pass-through" gateway changed generation and answers differed from talking to the backend directly; on OpenAI it was invisible because the injected values equal the API defaults. Cradle now forwards `model_dump(exclude_unset=True, exclude_none=True)` on both the miss and audit paths: only fields the client actually set go upstream (explicit values are kept even when they equal a default; vendor extras like `top_k` ride through), and an explicitly-sent optional null is not re-forwarded, so the payload is a strict subset of before. Cache identity is unchanged — `canonicalize` already reads the defaulted attributes, so an omitted `temperature` and an explicit `1.0` still share a key. (#26)
- **Audit self-heal now honors the write-quality gate.** On the first real-traffic run of verified L2, an audited wrong hit received an *empty* fresh answer from the upstream (`content: ""`, `finish_reason: stop`) and the self-heal cached that empty body under the querying prompt for the full TTL. The miss path's gate (`length` / `content_filter` / empty bodies are never stored) is now shared with the audit: a fresh answer that fails it yields verdict `error` (logged with the skip reason, counted in `cradle_cache_write_skips_total`), raises no floor, and writes nothing. (#24)
- **`X-Cradle-Cache-Control: refresh` now replaces the L2 point, not only the L1 entry.** The prompt was embedded only inside the L2 read that `refresh`/`no-cache` skip, so the writeback had no vector and the stale semantic point stayed behind: paraphrases (or the same prompt after L1 eviction) kept replaying the old answer as `HIT-L2`. The prompt is now embedded whenever it is L2-eligible; only the L2 lookup is skipped. (#18)
- **Fluff stripping now runs to a fixed point, so rule order and whitespace no longer hide pleasantries.** A user message that began with a space or newline (`" Please summarize …"`), ended with one (`"… thanks\n"`), or led with a filler before a pleasantry (`"just please …"`) kept text the rules were meant to remove, because the leading/trailing rules are anchored, only skip `[ ,.!]`, and ran once before the filler rule. The compressor silently saved fewer tokens on exactly the copy-pasted prompts it targets. The rules now iterate until nothing changes (they only ever remove text, so this terminates). Found by the new property tests, which pin idempotence. Cache keys are unaffected (they hash the canonical text, not the compressed one).
- **Wrap-mode streaming responses now preserve upstream token usage, real error detail, and provider metadata.** On the wrap (cacheable-miss) streaming path Cradle rebuilds the outbound stream, and three pieces of upstream truth were being lost: (1) **Token usage** — Cradle only asked upstream for usage when the *client* set `stream_options.include_usage`, so a client that omitted it caused an empty `usage: {}` to be cached; a later client that *did* request usage then replayed an empty usage frame. Cradle now always requests usage upstream on the wrap path (client-facing emission is still gated on the client's own flag), so the cached record and every replay carry the real `prompt_tokens`/`completion_tokens`. (2) **Errors** — a mid-stream upstream error was replaced with a generic `"upstream error"` string; the upstream's actual `message`/`type`/`code` now passes through verbatim. (3) **Metadata** — `system_fingerprint`/`service_tier` were dropped when the stream was rebuilt; they are now forwarded on the final usage chunk and stored so cached replays match live responses. The locally-generated `id`/`created` remain local by design (they must not mix upstream ids — see DESIGN.md). `pipeline_version` is bumped `v1`→`v2` so pre-fix wrap-stream entries (which stored empty usage) miss and age out on TTL rather than replaying without usage. On a streaming miss `X-Cradle-Upstream-Tokens` is now omitted rather than reported as a false `0` (the real count is only known after the body streams); it is still present on JSON responses and on streaming cache hits.
- **`/readyz` now reflects the reranker.** When `features.l2_rerank` is on (default) but the cross-encoder failed to load, `/readyz` reports `not_ready` (503) instead of `ready` — so a container never quietly takes traffic with the issue-#5 entity-swap protection off. Previously the health check ignored the reranker, so a load failure was invisible.
- **Cache identity now includes the resolved upstream backend.** Previously the L1/L2 cache key ignored which backend served a response, so changing a `routes:` mapping (or two named backends serving the same model glob) could replay the *old* backend's answers for the full TTL. Cache entries are now namespaced by the resolved route target + base URL. The cache schema bumped to 2, so pre-existing entries miss safely and age out on TTL.
- **Routing-only hints no longer split the cache.** Undeclared request fields that steer provider-side caching/routing but don't change the answer (`prompt_cache_key`, `prompt_cache_retention`, `safety_identifier`) were being hashed into the cache key, so two identical prompts differing only by such a hint cached separately — silently lowering hit rate. They are now excluded, like `stream`.
- Bypass streams (`stream+tools`, `n!=1`, logprobs) now forward upstream SSE bytes instead of stripping everything but `delta.content`.
- Upstream stream HTTP errors return JSON OpenAI errors before SSE starts.
- Truncated streams no longer fake `finish_reason=stop`.
- `pass_through_client_auth` actually forwards the client's `Authorization` header.
- `n!=1` JSON responses are returned unmodified (no wrap of only the first choice).
- Request body size is enforced on the actual body; invalid JSON is 400 not 500.
- Docker image creates a writable `/data` for user `cradle`.
- L2 startup refuses `WEB_CONCURRENCY` / `UVICORN_WORKERS` other than 1.
- Upstream connection failures return OpenAI JSON 502 instead of an uncaught 500.
- The `cradle_l2_points` gauge is updated on each L2 write, not only every 300s by the purge loop, so a fresh instance no longer reports 0 L2 points while actively serving semantic hits. The purge loop still reconciles the exact count. (#4)
